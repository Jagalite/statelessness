# Native BFS controls candidate receipts

This finite macOS/arm64 slice passed through Kyoto. It does not close N01,
promote an experimental profile, publish packages, establish performance, or
qualify other platforms/runtime floors/browser TypeScript.

`summary.json` records requested/effective commands and terminal states. The real
public Rust BFS executable matched all 47 independently derived report/callback
vectors, including six expected errors and no pointer-width skips. It was built
through Kyoto, then executed as a separate Kyoto job; build success alone is not
runtime evidence. The final native suites passed: Python 103 tests with 12 ABI
opt-in skips, Go uncached tests and vet with cgo disabled, Swift 66 tests, and
TypeScript 216 tests. Every engine consumes the shared 47-case corpus.

The current-source runs include exact admission/cutoff boundaries, newest-first
collision comparisons, failure-before-stop semantics, nullable/overflowed byte
estimates, u64-saturating skipped counts, detached rooted histories and partial
checker errors. TypeScript adds an exact BigInt API while preserving checked
Number compatibility. Go and TypeScript capture entry budgets rather than
retaining mutable caller aliases; cancellation state remains live. The Go
`go-cached-47` job is historical cache evidence, not the final corpus execution;
`go-final` explicitly uses `-count=1`.

`installed-r1/qualification.json` records five applications installed/staged
outside the checkout. Each matches base states/transitions/estimated bytes
3/6/15, capped 2/4/10, and pre-cancelled 0/0/unknown with zero callbacks. Observer
histories and failure target match. All 25 fresh-process witness producer/replayer
pairs passed using public recording/replay APIs.

`installed-r1/portable-baseline.json` separately verifies the four unchanged
portable profiles across five independent engines: each passed 94 goldens, 530
generated graphs, 32 metamorphic, 38 portability and 23 transport cases; all
550 baseline fresh-process replay combinations passed. New public report fields
are explicitly projected out of the established runner response schema.

Package/executable/source/artifact hashes and 52 command logs are retained. The
final native/reference package inputs were compared to the installed manifest
again after the run and remained unchanged. `source-inputs-final.json` identifies
all final source bytes; parent HEAD is the previous binary implementation commit,
so the manifest identifies this slice's uncommitted source precisely.

Earlier failed/partial runs are retained with their actual commands and logs:
legacy iterator-context/runner projection regressions were corrected, and the
Rust reference adapter initially omitted a required Model callback. Earlier
passing 43-case runs and runs before saturation/budget-snapshot fixes do not
qualify later source implicitly. No shared-queue policy was changed.

Append-only checking, sealed checked-result handoffs, richer/bounded replay,
recorder capture limits, remaining N01–N14 operations and broader release gates
remain open. State estimates exclude predecessor inputs, maps/frontiers,
temporary successors, callback allocations and RSS. Wrapper estimates follow the
explicit language-specific conventions in the candidate specification.
