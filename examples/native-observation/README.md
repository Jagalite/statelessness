# Installed observation consumers and qualification

These public consumers read the independently authored
[`conformance/observation-v1.json`](../../conformance/observation-v1.json).
The [contract](../../spec/observation-v1.md) is derived from Rust
`54ba3f32796fc5c71458fb4cda14b2ab9290ee83`, not generated by executing any engine.
The parent must commit and freeze the integrated candidate before qualification.
Nothing in this directory or an older receipt qualifies an unexecuted changed tree.

## Protocol

Every consumer accepts `observe fixturePath`, emitting exactly one UTF-8 JSON
object on stdout; diagnostic output belongs on stderr:

```json
{"schema":"statelessness.observation-results.v1","language":"python","cases":[{"id":"fixture-id","record_hex":"","callbacks":[],"error_stage":null,"sink_poisoned":false}]}
```

`language` is `python`, `go`, `typescript`, `swift`, or `rust`. Cases retain fixture
order. `record_hex` contains every delivered byte, including LF or a partial sink
prefix. Callbacks retain order and duplicates. Error stage is the first error;
sink health is final health. The validator compares the complete claimed object,
rejecting missing/extra fields, duplicate JSON keys, noncanonical hex and wrong
scalar kinds. It never normalizes record text, callbacks, check details, sequences,
or failure semantics. Fixture `record_text`, when present, must encode to its exact
`record_hex`; it is explanatory and does not occur in result cases.

Consumers use supplied event data and public observation APIs. They must not call
reducers, checks, initial-state generation, decoders, or effects to produce logging
output. Diagnostic events confer neither continuity nor checked-token authority.
Existing native checked tokens, periodic checks and bounded Recorder remain in use.

## Driver stages

[`qualify-native-observation.py`](../../scripts/qualify-native-observation.py)
accepts `--scope native|rust-compile|rust-runtime|installed`,
`--expected-commit COMMIT`, and `--output NEW_DIRECTORY`. All invocations belong
inside Kyoto jobs. The scripts never submit jobs or change queue policy themselves.

- `native` stages all native sources and their fixture dependencies outside the
  checkout, executes every `test_observation_*.py` validator/proof/process module
  with nonzero test counts and no skips or expected failures, then the full Python, Go,
  TypeScript and Swift suites. Existing Recorder/check-token tests remain included.
  Go uses `CGO_ENABLED=0`, recorded `GODEBUG=panicnil=0`, `-count=1` and `vet`; TypeScript builds and executes every
  `test/*.test.mjs`; Swift builds its XCTest bundle then executes with `--skip-build`
  and `--disable-swift-testing`. Python ABI opt-in skips are explicitly retained.
- `rust-compile` runs explicit Cargo `--no-run` compilation of `observation`,
  `monitor`, `monitor_limits`, `monitor_review`, `checked_replay` and `pr_review_core`,
  then compiles the standalone `validation/corpus` public `native-observation` and
  `native-checked` binaries.
  It accepts an optional fresh external `--cargo-target`. It captures Cargo's exact
  executable artifact records, toolchain identity, fixture and source manifests.
  A successful receipt means compilation only.
- `rust-runtime` requires `--compile-receipt PATH`. It verifies that receipt against
  the current committed source/fixture and actual executable hashes, discovers each
  test list, executes each whole matching binary, and requires every discovered
  test to pass with zero ignored/filtered tests. Discovery must match the pinned
  source-audited counts (13/10/11/3/14/6, totaling 57), which require a reviewed
  driver update if those test sources change. It then runs the Rust public
  consumer. This stage invokes no Cargo commands.
- `installed` requires `--compile-receipt PATH --rust PATH`. It builds and installs
  a Python wheel into an isolated environment (`-I` consumer), builds Go against a
  staged local module with CGO disabled, installs a TypeScript npm tarball into a
  separate strict declaration consumer with no Node type dependency, and builds a
  Swift source-package consumer. It verifies the installed root JavaScript export
  graph has no Node/bare dependency imports. Rust is the supplied executable from
  the prior source-bound compilation receipt. This stage invokes no Cargo commands.
  After Swift packaging it calls the parent-owned
  [`observation_authority.py`](../../scripts/observation_authority.py): two positive
  checked-token compilations and four expected diagnostic-type rejections for
  Go/Swift. Those are compile-control counts, not runtime counts.
  It then calls [`observation_suffix.py`](../../scripts/observation_suffix.py):
  interrupted and failing retained-suffix cases each require five real Recorder
  producers, 25 ordered binary replay pairs and 25 JSON replay pairs, all in fresh
  processes. Aggregate planned counts are 10/50/50. Independent contracts are
  [`suffix-contract.json`](suffix-contract.json) and
  [`suffix-failure-contract.json`](suffix-failure-contract.json). Counts are separate from
  observation fixture cases and validator bookkeeping; all remain unexecuted until
  the parent's frozen installed run succeeds.

[`check-native-observation-consumers.py`](../../scripts/check-native-observation-consumers.py)
is a second entry point for the same `installed` scope. The driver needs Python
3.11 or later. Python's isolated builder
needs setuptools >=77 and wheel; its exact installed tooling is inventoried.
Runtime package dependencies remain empty. Each native/installed attempt runs
`npm ci --include=dev --ignore-scripts --no-audit --no-fund` inside its external
staged package, using the sealed lock. No checkout `node_modules` or global
TypeScript compiler is required. The installed development tree is hashed before use.
Native compilation needs the already installed platform toolchains. No browser-host
runtime, Go race, full Rust workspace, doctest or `macro-qualification/monitor_release`
result is implied by these scopes.

## Freeze, identity and raw evidence

Every attempt must be a new directory under
`validation/native-parity/observation-slice/`. Existing directories are refused.
`attempt.json`, numbered per-command `started.json`/`finished.json`, separate raw
`stdout.bin`/`stderr.bin`, and final `receipt.json` are created exclusively. Failed
and timed-out processes retain bytes without replacement decoding, plus lengths
and SHA-256 when process termination is confirmed. Commands inherit Kyoto's PGID;
[`observation_process.py`](../../scripts/observation_process.py) tracks owned
descendants and performs bounded cleanup without signaling the scheduler group.
Unconfirmed cleanup preserves raw paths and fails without claiming final log hashes.
The driver has no graceful SIGTERM handler. Default-action SIGTERM, SIGKILL or
supervisor death can interrupt cleanup and receipt publication, leaving an
incomplete failed attempt. This is not evidence of confirmed cleanup or success.
Repeated labels receive new numbered directories; no old log is overwritten.
Staging and build directories are retained outside the checkout for inspection.

The seal includes source membership, file type, permissions, byte length and
SHA-256. Every consumed input in the worktree and committed HEAD must match the
requested committed tree; additions, missing files, mode/type changes and byte changes fail. The only
source exclusions are the designated observation receipt subtree and specifically
recognized Git-ignored build products. Ignored descendants of Rust source roots
are still included because `build.rs` consumes them. Historical receipts elsewhere
remain part of the seal. Sources are checked before and after commands and at exit.
Canonical manifests are content-addressed under `observation-slice/manifests/` and
shared across stages, so source equality is a manifest identity comparison.
HEAD may advance through receipt-only commits. Its nonreceipt committed tree must
still equal the source pin, as must the working tree. Before/after HEAD identities
are recorded separately; receipts retain the original `expected_commit` identity.

Every copied source is mapped back to its committed identity and checked before
and after commands, including builds and failures. Staged directory membership is
checked before consumption, rejecting injected Go/Swift sources. Explicit generated
inputs use `Attempt.register_generated(path, label)` before their first command;
the method watches them and refuses to rebaseline reused labels or paths. Only
designated generated build directories are excluded from staged source membership.
Built wheels/tarballs and Python builder package code are watched before consumption.
Installed Python and TypeScript package trees and built consumer executables are
watched before their first consuming command. Python entry points and generated
test runners use `-I -B`; generated runner directories have sealed membership,
and only explicit staged source/test roots join their import path. Qualification
helpers load source bytes directly, so an ignored bytecode cache cannot replace
the hashed helper source. Trusted host standard libraries and toolchains remain
outside this source contract.
Compile receipt reuse delegates to
[`observation_compile_proof.py`](../../scripts/observation_compile_proof.py), validating
retained commands, raw-log hashes, start/finish records, content-addressed manifests,
exact Cargo commands and compiler-artifact package/source/profile/executable records.
Missing or corrupt compile evidence fails admission even if an executable still exists.
Aggregate raw-log sealing also reconciles nested Go wrapper start/finish journals
and receipts. An uncertain or incomplete nested writer prevents final raw-log
hashes even when the outer command has exited; the original paths remain retained.

Receipts retain package/fixture/compiler/runtime file identities, staged artifacts,
the actual Rust and Go test executable identities, commands and relevant environment.
Installed runtime package trees and runner files are checked before/after execution.
This local evidence is not a cryptographic attestation of an untrusted host and
cannot detect a temporary mutation restored entirely between snapshots. Process
ownership uses sampled ancestry, not containment against rapid daemonization. Keep the
parent's freeze in force throughout every stage.

Validator negative controls independently mutate result bytes, callback counts,
first error, sink health/type, case identity/membership, extra fields, fixture
expectations and single-record byte bounds. Those rejection counts are separate
from `language_executed_cases`. Unit tests also exercise binary log preservation on
failure/timeout, exclusive evidence creation, committed binary content, source
membership/mode/type drift, ignored source additions and manifest collisions.
These validator tests run in `native`; their success is not a language execution.

## Exact continuation commands

These are continuation commands for the parent **after** it freezes/commits the
integrated sources. They have not been submitted or executed by this source-only
task. Run from this worktree; use fresh attempt/target names after any failure.
Do not run installed/runtime scopes before the successful compile receipt exists.

```sh
OBS_COMMIT="$(git rev-parse HEAD)"
# Keep this original source pin for all dependent commands, even if receipt-only
# commits subsequently advance HEAD. The compile receipt binds this value.
OBS_RECEIPTS="$PWD/validation/native-parity/observation-slice"
OBS_TARGET="${TMPDIR:-/tmp}/stateless-observation-${OBS_COMMIT}-a1"

python3 /Volumes/seed1/Projects/kyoto/kyoto.py submit -- \
  python3 -I -B scripts/qualify-native-observation.py --scope native \
  --expected-commit "$OBS_COMMIT" --output "$OBS_RECEIPTS/native-a1"

python3 /Volumes/seed1/Projects/kyoto/kyoto.py submit -- \
  python3 -I -B scripts/qualify-native-observation.py --scope rust-compile \
  --expected-commit "$OBS_COMMIT" --cargo-target "$OBS_TARGET" \
  --output "$OBS_RECEIPTS/rust-compile-a1"

# After inspecting the successful rust-compile receipt and its binary paths:
python3 /Volumes/seed1/Projects/kyoto/kyoto.py submit -- \
  python3 -I -B scripts/qualify-native-observation.py --scope rust-runtime \
  --expected-commit "$OBS_COMMIT" \
  --compile-receipt "$OBS_RECEIPTS/rust-compile-a1/receipt.json" \
  --output "$OBS_RECEIPTS/rust-runtime-a1"

python3 /Volumes/seed1/Projects/kyoto/kyoto.py submit -- \
  python3 -I -B scripts/check-native-observation-consumers.py \
  --expected-commit "$OBS_COMMIT" \
  --compile-receipt "$OBS_RECEIPTS/rust-compile-a1/receipt.json" \
  --rust "$OBS_TARGET/debug/native-observation" \
  --output "$OBS_RECEIPTS/installed-a1"
```

Use Kyoto `show JOB_ID`, `logs JOB_ID`, and `wait JOB_ID` to inspect each actual
command/result. No successful compile-only job is an executed test receipt.

## Scope of the retained-suffix gate

The parent-added `record-suffix` modes export actual one-step retained Recorder
suffixes after eviction for interrupted and failing runs, with origin 40 and
observed absolute turns 41/42 and 41/42/43 respectively, while
NoPayloads diagnostics observe the same checked execution without rechecking it.
The installed helper compares literal rich/bounded observations, portable bytes,
binary framing/footer, callback counts, observer text and ordered provenance
counters. The failing case requires `freeze_verified: true` and exact post-freeze
diagnostic text, backed by producer assertions comparing actual before/after
artifacts. It reuses the public `replay-suffix`/`replay-suffix-json` modes. It does not
certify the evicted prefix or substitute for full native/selected Rust suites,
long-session coverage, broader N07 acceptance requirements or platform/resource
qualification. A prepared driver or a historical checked-driver receipt proves
none of these newly changed sources executed successfully.
