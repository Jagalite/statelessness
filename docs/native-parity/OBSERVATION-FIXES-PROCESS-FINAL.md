## P1 finding and correction

The final driver reviewer found that `_DarwinProcesses.read` passed zero as the
`arg` of `proc_pidinfo(pid, PROC_PIDTBSDINFO, arg, ...)`. If the direct `Popen`
child had already exited but remained unreaped, the kernel omitted its zombie
entry, the wrapper reported `ESRCH`, and `_Owner` rejected a valid command as
disappeared/already reaped. The existing mocked backend test also required zero,
so it could not expose the real kernel behavior.

The production query now passes **1** and explains why. The mocked ABI assertion
also expects 1. The change preserves the existing PID/start-time identity, PPID
ownership validation, inherited PGID check, and separate zombie classification.
It does not accept an absent or unreadable identity as ownership evidence.

Primary contract inspected at Apple XNU commit
`f6217f891ac0bb64f3d375211650a4c1ff8ca1ea`:

- [`bsd/kern/proc_info.c`, lines 2046-2064](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/kern/proc_info.c#L2046-L2064)
  enables zombie lookup for `PROC_PIDTBSDINFO` only when `arg` is nonzero;
  unsuccessful live lookup then falls back to `proc_find_zombref`. Otherwise a
  zombie-only PID yields `ESRCH`.
- [`libsyscall/wrappers/libproc/libproc.c`, lines 94-103](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/libsyscall/wrappers/libproc/libproc.c#L94-L103)
  forwards `arg` to the syscall and converts its `-1` result into zero while
  retaining errno.
- Installed SDK files under
  `/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/usr/include/` confirm the
  `uint64_t arg` declaration (`libproc.h:96`), flavor 3 and the size macro
  (`sys/proc_info.h:723-724`), and the `proc_bsdinfo` fields including PPID, PGID,
  status, and start seconds/microseconds (`sys/proc_info.h:59-82`). This is source
  evidence; it is not a claim that the running kernel was exercised.

## Authored regression and control

`test_darwin_already_exited_unreaped_child_binds_without_signals` covers both
successful exit 0 and nonzero exit 7. Each fixture writes literal binary stdout
and stderr and exits. Before `wait_owned`, a bounded raw libproc query with
explicit `arg=1` confirms `SZOMB` and the child PID/PPID/inherited PGID without
calling `Popen.poll`, `wait`, or `communicate`. The gate does not call the backend's
`read` method, so reverting its argument to zero still reaches the regression
with an actual exited, unreaped child.

The regression requires the original return code, retained start fingerprint and
zombie receipt, inherited PGID, confirmed observed-process termination, stable
literal binary streams, no ownership errors, and no signal calls. The helper
must reap its own child normally. A fixed sleep alone is not its exit oracle.

`test_darwin_backend_zombie_lookup_flag_and_live_control` separately establishes
the raw negative control (`arg=0` returns zero/`ESRCH` for the same unreaped
zombie), checks that the corrected backend returns its full identity and zombie
status, and checks a live identity using the current test process. Existing
mocked permission/truncation/disappearance controls remain intact. Both new real
tests are explicitly Darwin-only; a Linux run skips them and cannot qualify the
Darwin correction. Fixture output literals are authored expectations, not values
generated by executing an implementation.
