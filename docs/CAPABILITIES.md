# Capabilities, versions, and qualification

This is the source capability index. All public packages and portable profiles
are experimental. **Implemented**, **qualified**, and **published** describe
different facts: an API can exist in this checkout without being present in a
registry release or tested on a particular platform.

The matrix is generated by `python3 scripts/check-capabilities.py --write` from
package/protocol declarations and reviewed scope/evidence entries in that script.
Run the script without arguments to detect drift. Generation checks documentation
and version alignment; it does not build packages, execute tests, or establish
feature completeness. Update the scope entries when APIs change.

Qualification links below contain historical evidence and its limitations.
Their source revisions, artifact hashes, platforms and test modes define the
qualified scope; results do not transfer automatically to this checkout. The
[improvement status](improvement/STATUS.md) tracks implementation across the improvement roadmap. New workflow gates
being configured does not mean their hosted runs have passed. A new runtime
qualification and measured benchmark baseline remain pending until receipts exist.

## Source checkout and registry release

On 2026-10-12 the crates.io APIs reported `statelessness` and
`statelessness-macros` **0.2.0** as published and unyanked. Their downloaded archive
SHA-256 hashes matched the registry checksums; both archives name source commit
`2af92dfdc0b0d0b0a76848a67bf9c4804b3bb116`. The debugger crate lookup returned
404. The [registry receipt](../validation/releases/2026-10-12-registry.json)
records URLs, archive hashes and source identities. This checks availability and
artifact identity only; it is not an installed-consumer or runtime test.

The newer source checkout still uses 0.2.0 manifests. That version number alone
does not identify its APIs or bytes. For current-source APIs, use a local path
dependency and matching local companions as shown in [README](../README.md).
For a registry installation, consult the documentation shipped with that exact
release. In particular, the new debugger and inspection derives are not made
available by installing the older published macro/core archives.

Python, Go, TypeScript and Swift source versions are independent from the Rust
crate versions. The native TypeScript package is `@jagalite/statelessness`; the
Rust/Wasm wrapper is `@jagalite/stateless`. The root SwiftPM product is the native
`Statelessness`; the binding product is `StatelessNative`. The browser binding's
source package manifest is a template: `scripts/build-bindings.py` substitutes
the root Rust package version when staging its distributable package.

## Capability boundaries and planned work

All four independent native ports retain the four established profiles:
`core-v1`, `bfs-v1`, `rng-splitmix64-v1`, and `trace-json-v1`. All four native engines
also implement the **candidate** `paired-v1` oracle/projection contract and share
an independently declared finite corpus with Rust. It is excluded from `PROFILES`
and listed as experimental. See [native parity status](NATIVE-PARITY-STATUS.md)
for current implementation and execution boundaries. Candidate
code and schema-valid fixtures do not establish independent review, full
cross-language runtime qualification, or promotion into the portable contract.
All four native engines additionally contain the experimental `search-v1`
generation/fuzz/shrink candidate, including search observer hooks and oracle
generation forwarding. These APIs remain outside the four qualified profiles.
Guided campaigns, lifecycle helpers, multi-machine scheduling, runtime ring
recorders and binary `.sttrace` parity remain open native gaps.

The Rust-backed C/Swift/JavaScript/Go interfaces call the Rust engine through ABI
1 and expose recording, replay and finite enumeration. Generic foreign fuzz,
shrinking, campaigns and runtime ring recording are absent. The Go jobs example
has a specialized paired Rust harness; it does not add generic SDK APIs.

Current Rust source adds optional assurance manifests with separately reported
properties, search termination, input families and cover goals; an application
controller and seeded fault-control gate; explicit multi-machine routing; bounded
lifecycle retention; and a v2 evidence envelope around preserved exact v1 data.
See [assurance](ASSURANCE.md), [integration](INTEGRATION.md),
[lifecycle/network](improvement/LIFECYCLE_AND_NETWORK.md), and
[evidence](EVIDENCE.md). These are current-source capabilities, not additions to
the already published 0.2.0 archives. Independent review of the controller's
requirements is still pending.

The debugger adds passive diagnostic reports and causal origin joins plus an
offline evidence viewer with explicit omitted-prefix and phase boundaries.
[Diagnostic reports](DIAGNOSTIC_REPORTS.md) keep unknown samples and health losses
visible; exporters are explicit optional diagnostic data, never exact evidence.
A TUI, network transport and native LLDB/GDB launch integration remain absent.

[New benchmark suites](benchmarks.md) separate retained-state/history growth,
checks, traces, composition, observation and diagnostic costs. Authored benchmark
code has no measured result until executed. Structural sharing/checkpoint cadence
and reduced equality are experiments, not new defaults or performance claims.
The [reduction research harness](REDUCTION_RESEARCH.md) only compares explicit
finite fixtures and retains a known unsound-projection counterexample; it does not
prove a general reduction algorithm sound. General liveness and distributed
partial-order reduction remain research.

The current task retains Kyoto's compile-only policy. Historical M0 receipts do
not qualify the new modules. Local Rust runtime tests, live controller execution,
mutation kills, benchmark distributions and hosted CI outcomes require separate
current-source receipts before being claimed as passed.

## Reading guarantees and compatibility

- **Exact replay** compares the recorded checkpoint and ordered observations for
  that prefix. **Guided search** uses feature novelty to choose more cases; neither
  establishes exhaustive model coverage.
- **Graph exhausted** means the declared finite reachable graph has been explored.
  A depth, state, transition or time limit leaves exploration incomplete. Every
  claim is conditional on the supplied input domain, properties and state equality.
- A **skipped check** is recorded and is not a pass. An **absent property** has no
  observation at all; a zero skip count cannot establish specification adequacy.
- A **logical deadline** is modeled data. It does not establish real scheduler
  fairness, wall-clock completion, or correctness of the application's effect host.
- **Exact traces** retain model/codec bytes for replay and may contain secrets.
  Redacted **diagnostic projections** are separate and cannot replace exact evidence.
- State equality and hashing must retain everything affecting future behavior,
  inputs and properties, including oracle/history state. An evicted runtime prefix
  is outside the retained history; replay covers the checkpoint and retained suffix.

Package versions, model/property/codec identities and wire protocol versions are
separate compatibility dimensions. Build mismatch opt-in bypasses build identity
only. It does not waive model/property/codec mismatches. Portable JSON envelopes
are not lossless Rust binary audit traces. A v1 trace does not preserve every state-versus-transition phase, so its
debugger minimization requires an explicit target phase. The optional v2 envelope
preserves and validates phase boundaries before replay or minimization. Validate upgrades with matching packaged consumers and fresh-process
replay; do not silently change a versioned wire format.
